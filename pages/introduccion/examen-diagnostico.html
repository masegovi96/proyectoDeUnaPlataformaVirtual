Examen Diagnóstico

Objetivo

Evaluar el nivel del estudiante en:

  • Pensamiento lógico aplicado a software
  • Ingeniería de requisitos
  • Modelado básico
  • Conocimiento de metodologías
  • Toma de decisiones técnicas
Importante
Este examen no tiene valor en la calificación final
Es únicamente diagnóstico
Evita el uso de inteligencia artificial
Caso Práctico

Se te plantea el siguiente problema:

Una escuela desea un sistema web para gestionar asesorías entre alumnos y profesores. Los alumnos podrán solicitar asesorías y los profesores podrán aceptar o rechazar solicitudes.

Actividad

1
Análisis de Requisitos
  • Requisitos funcionales (mínimo 5)
    Ejemplo: El alumno puede registrarse
  • Requisitos no funcionales (mínimo 3)
    Ejemplo: El sistema debe ser rápido
2
Modelado
  • Diagrama de casos de uso (básico)
    Incluye al menos: Alumno, Profesor
  • Flujo del proceso
    ¿Qué ocurre desde que el alumno solicita asesoría hasta que el profesor responde?
3
Metodología
  • ¿Qué metodología usarías?
    Ejemplo: Scrum, Cascada. Explica por qué en este caso.
  • Organización del trabajo
    ¿Trabajarías en equipo o individual? ¿Cómo dividirías el trabajo?
4
Diseño
  • ¿Qué componentes tendría el sistema?
    Ejemplo: frontend, backend, base de datos
  • ¿Qué tecnología usarías?
5
Pensamiento de Ingeniería
  • ¿Qué problemas podrían surgir?
    Mínimo 3
  • ¿Cómo mejorarías el sistema en el futuro?
6
Patrones de Diseño
  • ¿Aplicarías algún patrón de diseño?
    Ejemplos: MVC, Singleton. Explica brevemente por qué.
Entrega
  • Documento PDF o escrito
  • Puede incluir diagramas a mano o digitales
  • Subirlo a GitHub
