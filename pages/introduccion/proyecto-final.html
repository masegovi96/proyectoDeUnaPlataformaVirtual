Proyecto Final

Desarrollo de un sistema de software funcional con cliente real durante el cuatrimestre

Objetivo

Desarrollar un sistema de software funcional, trabajando con un cliente real, aplicando principios de ingeniería de software, gestión de proyectos e ingeniería de requisitos.

Modalidad de trabajo
  • Equipos de 4 integrantes
  • Cada equipo trabaja con un cliente real
  • Desarrollo progresivo durante el cuatrimestre
Descripción general

Cada equipo deberá:

  • Identificar una problemática real
  • Trabajar directamente con un cliente
  • Levantar y validar requerimientos
  • Diseñar una solución tecnológica
  • Desarrollar un sistema funcional
  • Documentar todo el proceso
Alcance del sistema

El proyecto deberá ser un sistema completo y funcional:

  • Interfaz de usuario (frontend)
  • Lógica del sistema (backend)
  • Base de datos (obligatorio)
  • Flujo funcional completo
El sistema debe resolver un problema real planteado por el cliente
Toma de decisiones tecnológicas

Cada equipo deberá seleccionar y justificar las tecnologías que utilizará, adaptándolas a las necesidades del proyecto.

No se impondrán tecnologías específicas
Se evaluará la coherencia entre la solución y el problema

Proceso de desarrollo

1
Ingeniería de requisitos

Levantamiento con el cliente, definición de requisitos funcionales y no funcionales, y validación continua.

2
Diseño del sistema

Arquitectura general, modelado de datos, diagramas, prototipos e interfaces.

3
Desarrollo

Implementación del sistema, integración frontend + backend y conexión con base de datos.

4
Pruebas

Validación de funcionalidades y corrección de errores.

5
Gestión del proyecto

Organización del equipo, planeación del trabajo y seguimiento de avances.

Roles del equipo
  • Líder de proyecto
  • Desarrollador frontend
  • Desarrollador backend
  • Responsable de BD / QA / documentación
Todos los integrantes deben participar activamente
Seguimiento y revisiones

Se realizarán revisiones periódicas con el docente. Cada equipo deberá presentar avances funcionales.

Se evaluará:

  • Progreso real
  • Organización
  • Cumplimiento de objetivos
Documentación
  • Descripción del problema
  • Requisitos
  • Diseño del sistema
  • Modelo de base de datos
  • Evidencia del desarrollo
  • Manual básico de uso
El formato será indicado durante el curso

Presentación final

Fecha 14 de agosto Presencial
Características
  • Presentación por equipo
  • Demostración del sistema en funcionamiento
  • Explicación del proceso
  • Justificación de decisiones técnicas
Público
  • Personas invitadas
  • Simulación de entorno profesional real
Durante la presentación

El equipo deberá:

  • Explicar el problema
  • Presentar la solución
  • Mostrar el sistema funcionando (obligatorio)
  • Explicar tecnologías utilizadas
  • Justificar decisiones

Rúbrica de evaluación

Criterio Descripción %
Funcionalidad El sistema funciona correctamente y resuelve el problema planteado 25%
Base de datos Diseño adecuado, relaciones correctas y uso funcional 15%
Desarrollo técnico Integración frontend-backend, lógica y estructura del código 15%
Ing. de software Requerimientos claros, diseño y uso de diagramas 10%
Documentación Completa, clara y bien estructurada 10%
Trabajo en equipo Organización, roles y participación 10%
Presentación Claridad, dominio y demostración funcional 10%
Toma de decisiones Justificación de tecnologías y soluciones 5%
